Enviar sua primeira mensagem

Faça uma chamada à API do Sinal e receba o status de entrega no seu servidor, em menos de dez minutos.

Leitura: 6 minAtualizado em 18 de novembro de 2026API v1

Antes de começar#

Você precisa de uma conta no Sinal e de uma chave de API do ambiente de testes. Mensagens enviadas com chaves de teste não chegam ao destinatário e não geram cobrança.

Guarde a chave no servidor. Nunca coloque SINAL_API_KEY em código de navegador ou de app. Se ela vazar, revogue em Painel › Chaves de API.

Passo a passo#

  1. Instale o SDK

    Use o pacote oficial para Node.js 18 ou superior.

    terminal
    npm install @sinal/node

  2. Configure a chave

    Defina a variável de ambiente antes de iniciar a aplicação.

    .env
    SINAL_API_KEY=sk_teste_51Nq0aXb7VdE2mH

  3. Envie a mensagem

    Informe o canal, o destinatário em formato E.164 e o texto.

    import { Sinal } from "@sinal/node";

const sinal = new Sinal(process.env.SINAL_API_KEY);

const mensagem = await sinal.mensagens.criar({
  canal: "sms",
  para: "+5511987654321",
  texto: "Seu pedido #4821 saiu para entrega.",
  referencia: "pedido-4821", // ajuda a conciliar depois
});

console.log(mensagem.id, mensagem.status); // msg_8fK2… "na_fila"
    curl https://api.sinal.dev/v1/mensagens \
  -H "Authorization: Bearer $SINAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "canal": "sms",
    "para": "+5511987654321",
    "texto": "Seu pedido #4821 saiu para entrega."
  }'

  4. Confirme a resposta

    Uma resposta 202 Accepted significa que a mensagem entrou na fila. O status final chega por webhook.

Parâmetros da requisição#

CampoTipoObrigatórioDescrição
canalstringSimsms, whatsapp ou email.
parastringSimNúmero em E.164 (por exemplo +5511987654321) ou e-mail.
textostringSimAté 1.600 caracteres. SMS longos são divididos em partes.
referenciastringNãoSeu identificador interno. Volta igual nos webhooks.
agendar_parastringNãoData ISO 8601 até 30 dias à frente.

Entender o status#

Cada mensagem passa por na_fila, enviada e entregue. Se a operadora recusar, o status final é falhou e o campo motivo explica o que houve.

Erros comuns#

Se a chamada falhar, confira o código HTTP antes de tentar de novo. Erros 4xx não se resolvem repetindo a requisição.

Use o cabeçalho Idempotency-Key em reenvios. Assim, uma falha de rede não gera duas mensagens para o mesmo cliente.
